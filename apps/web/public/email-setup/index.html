Gmail through Apps Script

Send PartCast sign-in codes and reviewed supplier emails through your own Google script. This uses HTTPS on Render Free, with no custom domain or IP allowlist.

Your Google account must authorize the script. A public Google app branding review is separate from this owner authorization. Google account restrictions can still prevent deployment or authorization.

A standard personal Google account typically has an Apps Script limit of 100 email recipients per day, shared by sign-in codes and supplier emails. Your account’s actual allowance may differ. See Google’s current quotas.

1. Create your script

Sign in to Google Apps Script as npgautoparts@gmail.com. Create a new project named PartCast Email. Replace everything in Code.gs with this script, then save.

Download Code.gs

View script
Use Copy script or Download Code.gs to get the complete script.

2. Create a signing key

This private key lets PartCast authenticate each request. It is generated on this device and is not saved by this page. Use the same key in Google and Render.

In the script editor, open Project Settings → Script properties → Add script property:

Property: PARTCAST_MAIL_SECRET
Value: paste your generated signing key

Save the property. Keep the key privately; it is not your Gmail password.

3. Authorize and deploy

Return to the editor. Select authorizePartCast beside Run, then choose Run → Review permissions. Authorize your own project to send email from the signed-in account.

If Google shows an unverified-app warning for the project you just created, check the project/account, then use its Advanced option to continue to your own script. If Google blocks authorization entirely, this setup cannot proceed for that account; report the exact error without sharing credentials.

Select Deploy → New deployment → Web app:

  • Execute as: Me (npgautoparts@gmail.com)
  • Who has access: Anyone

Choose Deploy and copy the web app URL ending in /exec. Use the deployed URL, not the editor or test URL. The script rejects requests without the matching signature.

4. Configure Render

Open the API service serving partcast.onrender.com. Under Environment, set these server variables:

GMAIL_DELIVERY_METHOD=apps_script
GMAIL_SENDER_EMAIL=npgautoparts@gmail.com
GMAIL_APPS_SCRIPT_URL=your deployed /exec URL
GMAIL_APPS_SCRIPT_SECRET=your generated signing key

Save and redeploy the API. Wait for Live. Keep existing security/encryption keys unchanged.

5. Clear the previous email override

After the new environment values are set, open your existing Supabase project’s SQL Editor and run:

delete from public.integration_settings
where provider = 'gmail';

This removes the saved Gmail connection so the API uses Render’s values. It preserves staff accounts, store records and Gemini settings. No SQL migration is needed.

6. Check delivery

Wait 20 seconds, open PartCast sign in, and request one code. Use the most recent code. If it fails, expand Error details and share only the Reference line.

Once signed in as Super Admin, IT settings also supports Gmail via Apps Script. Its connection check sends no email; a completed sign-in confirms that your code arrived.

To update this script later, use Deploy → Manage deployments → Edit → New version → Deploy. To disconnect it, archive its deployment and remove its Google account authorization. Google MailApp delivery does not promise that a Gmail Sent copy will exist; check the recipient or PartCast’s supplier sending result.
